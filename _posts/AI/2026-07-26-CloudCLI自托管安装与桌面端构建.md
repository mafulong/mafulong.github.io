[CloudCLI](https://github.com/siteboon/claudecodeui)（aka Claude Code UI）是一个开源的 AI 编程 Agent 统一 Web/桌面 UI，覆盖 Claude Code / Cursor CLI / Codex 三种 CLI。它自己不带 AI，用你自己的 Claude / Cursor / OpenAI 订阅，在浏览器、移动端、原生桌面端用同一套界面跑文件浏览、Git 操作、xterm 终端、MCP 管理。

相比单独跑 CLI 的差异：

- 一个 UI 切三种 agent，不重启 server
- 自动发现 `~/.claude` 里所有已有会话（不是只暴露当前活跃那条）
- 设置直接写回原生 Claude Code 配置（不是数据复制，是同一份）
- 移动端浏览器访问 `http://<电脑内网IP>:3001` 就能用
- 可选 PWA + Web Push 通知

## 安装方式

| 形态 | 适合 | 命令 |
|---|---|---|
| **Self-hosted npm**（本文重点） | 本地开发、机器一直开着、想用桌面端 | `npx @cloudcli-ai/cloudcli` |
| Docker Sandbox（实验） | 需要 microVM 隔离的 agent 环境 | `npx @cloudcli-ai/cloudcli@latest sandbox ~/project` |
| CloudCLI Cloud（€7/月起） | 云端跑、团队共享、不想自己维护 | <https://cloudcli.ai> |

下面只讲 self-hosted。

## 前置依赖

- **Node.js 22+**（实测 v24 也行；`.nvmrc` 写 v22）

  ```bash
  node --version    # 确认 >= v22
  ```

- **macOS / Linux / Windows**（桌面端官方包仅 macOS / Windows）
- 8GB+ 内存（Electron + 原生模块比较吃）
- 1.5GB+ 磁盘（`node_modules` 会涨到 1.1-1.4GB）

## 方式一：npx 一行命令（最快上手）

```bash
npx @cloudcli-ai/cloudcli
```

启动后访问 `http://localhost:3001`，自动发现 `~/.claude` 里已有的会话。

或者全局装：

```bash
npm install -g @cloudcli-ai/cloudcli

cloudcli             # 启动 server
cloudcli status      # 看配置和路径（数据目录、监听端口、安装模式）
cloudcli version     # 打印版本
cloudcli --help      # 所有子命令
```

## 方式二：从源码构建 + 打桌面端

适合想改前端、做插件开发、或需要未签名本地包的人。

### 克隆 + 装依赖

```bash
git clone https://github.com/siteboon/claudecodeui.git
cd claudecodeui

# 装依赖（含 Electron、better-sqlite3、node-pty 等原生模块，约 18 分钟）
npm install
```

装完会跑 `postinstall`（自动 chmod `node-pty/spawn-helper`，macOS 进程隔离要求）和 `prepare`（husky）。`node_modules` 大约 1.1-1.4GB。

### 构建产物

```bash
npm run build
# 产出：dist/（前端 7MB）+ dist-server/（后端 2.7MB）

# 只改前端代码时
npm run dev                # 同时起 server:dev (tsx 监听) + Vite (HMR)

# 只改服务端时
npm run server:dev-watch

# 类型检查 / Lint
npm run typecheck
npm run lint
```

### 出未签名 .app（macOS，本地自用）

```bash
CSC_IDENTITY_AUTO_DISCOVERY=false npm run desktop:pack
```

产物在 `release/desktop/mac-arm64/CloudCLI.app`（Intel 是 `mac/`），双击就能跑。

**为什么要 `CSC_IDENTITY_AUTO_DISCOVERY=false`？** 项目默认 `mac.notarize: true`，没 Apple Developer 凭证会卡在公证。设这个环境变量跳过签名 + 公证，本地使用足够。首次打开右键 → 打开（Gatekeeper 绕过）即可。

### 出 dmg / nsis 分发包

```bash
npm run desktop:dist:mac      # macOS dmg
npm run desktop:dist:win      # Windows nsis
```

需要 Apple Developer 凭证：

```bash
export CSC_LINK=/path/to/DeveloperID.p12
export CSC_KEY_PASSWORD=...
export APPLE_ID=you@example.com
export APPLE_APP_SPECIFIC_PASSWORD=...
export APPLE_TEAM_ID=ABCDE12345
npm run desktop:dist:mac
```

### 桌面 + Vite HMR 联调

```bash
npm run desktop:dev          # Electron 嵌 Vite dev server (端口 5173)
```

## 配置与目录速查

```bash
# 全局装的 cloudcli 数据目录
~/.cloudcli/

# 关键文件
~/.cloudcli/local-server.json                       # 当前 local server 状态（PID、port、URL）
~/Library/Application Support/CloudCLI/             # Electron desktop userData（macOS）

# 复制一份配置改
cp .env.example .env
nano .env        # 主要项：SERVER_PORT、VITE_PORT、HOST

# Claude 原生会话位置（CloudCLI 直接读这里）
~/.claude/projects/<encoded-path>/<session-id>.jsonl

# Codex 原生会话
~/.codex/sessions/
```

## 安全提醒：tools 默认全关

第一次进 UI，CloudCLI 会提示 **所有 Claude Code tools 默认禁用**。这是有意设计 —— 防止 agent 误操作。

打开 **Settings → Tools Settings**，按需开启。建议从基础工具（Read、Bash 白名单）开始，逐步放开。

## 几个值得知道的事实

1. **CloudCLI 读 `~/.claude`**：你在 UI 里加的 MCP server / 改的工具权限，会写到原生 Claude Code 配置里，反之亦然。不是数据复制，是同一份。
2. **三个 CLI agent 共用一套 UI**：Claude Code（SDK 直连）、Cursor CLI（spawn + stream-json）、Codex（SDK）。切换不需要重启 server。
3. **桌面端是 launcher，不是 Electron-only**：默认是 CloudCLI Cloud 入口 + 本地 server 切换器。想完全跳过：

   ```bash
   # 直接跑 server，浏览器访问 3001
   node /path/to/claudecodeui/dist-server/server/index.js

   # 装好的 .app 内部 server
   node /path/to/CloudCLI.app/Contents/Resources/app/dist-server/server/index.js
   ```

4. **会话数据由 provider 自存**：UI 不重复存，SQLite 只存元数据（项目路径、会话索引、用户、推送订阅）。
5. **macOS 进程隔离**：`node-pty` 的 `spawn-helper` 二进制 postinstall 自动 chmod，不然首次启动终端会失败。

## 升级 / 卸载

```bash
# 升级（npm 全局版）
npm update -g @cloudcli-ai/cloudcli

# 升级（源码）
cd claudecodeui
git pull
npm install
npm run build
CSC_IDENTITY_AUTO_DISCOVERY=false npm run desktop:pack

# 卸载（全局版）
npm uninstall -g @cloudcli-ai/cloudcli

# 清数据（注意会丢项目列表、用户、推送订阅）
rm -rf ~/.cloudcli/
```

## 常用命令速查

| 命令 | 作用 |
|---|---|
| `npx @cloudcli-ai/cloudcli` | 一键启动（不装） |
| `cloudcli` / `cloudcli start` | 全局版启动 server |
| `cloudcli status` | 看配置、路径、运行状态 |
| `cloudcli version` / `cloudcli --help` | 版本 / 子命令 |
| `npm run dev` | 前端 + 服务端一起 dev |
| `npm run server:dev-watch` | 只重启服务端 |
| `npm run build` | 出 dist/ + dist-server/ |
| `npm run desktop:pack` | 出未签名 .app |
| `npm run desktop:dist:mac` | macOS dmg（需 Apple 凭证） |
| `npm run desktop:dist:win` | Windows nsis |
| `npm run typecheck` / `npm run lint` | 静态检查 |
| `lsof -i :3001 -sTCP:LISTEN` | 看 server 是否在跑 |
| `lsof -ti :3001 \| xargs kill` | 杀进程 |

```bash
# Server 日志直接 stdout
node dist-server/server/index.js

# 桌面端启动日志
tail -f ~/Library/Logs/CloudCLI/main.log     # macOS

cloudcli
```

## 常见问题

**Q: 一定要装桌面端吗？**
A: 不必须。`npm install -g @cloudcli-ai/cloudcli` 然后 `cloudcli` 就够了，浏览器访问 3001。桌面端是多一层 macOS 窗口 + 托盘 + 开机启动。

**Q: 能在 Windows 用吗？**
A: 服务端可以（Node 跨平台），桌面端有官方 nsis 安装包（GitHub Releases 下 `cloudcli-desktop-*-win-*.exe`）。

**Q: 移动端怎么访问？**
A: 服务端默认监听 `0.0.0.0:3001`，同一 Wi-Fi 下手机浏览器访问 `http://<电脑内网IP>:3001` 即可。要改：

```bash
HOST=0.0.0.0 cloudcli       # 或在 .env 里改
```

**Q: 自带推送通知吗？**
A: 是。Web Push + Service Worker + VAPID。

**Q: 插件怎么装？**
A: UI 里 **Settings → Plugins**，粘贴 git repo URL 即可。或者基于 starter 模板自己做：

```bash
git clone https://github.com/cloudcli-ai/cloudcli-plugin-starter.git
cd cloudcli-plugin-starter
npm install
# 按 README 配置 manifest.json 和 plugin.config.js
```

**Q: 怎么知道当前跑的是哪个版本？**

```bash
cloudcli version                                            # 全局版
cat package.json | grep '"version"'                         # 源码
curl http://localhost:3001/health                           # 前端实际跑的版本
# {"status":"ok","timestamp":"...","version":"1.36.3"}
```
