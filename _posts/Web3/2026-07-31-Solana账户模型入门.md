# Solana 账户模型入门（结合 Swap / 收款场景）

> 整理自日常答疑：`toAddress` → ATA、余额存在哪、Program / PDA / Mint / Owner、以及「进合约再转出」如何一笔完成。  
> 目标：能看懂 Explorer，能设计「用户付款 → 程序金库 → 收款人」的单 tx 流程。

---

## 0. 和 EVM 的最大差异（先建立直觉）

| | EVM | Solana |
|--|-----|--------|
| 合约 | 代码 + storage 在一起 | Program（代码） 与 Account（数据） 分离 |
| 代币余额 | 常在 ERC20 合约的 mapping(address => uint) | 在独立的 Token Account 里，不在 Mint「合约」里 |
| 用户地址 | 直接有 token 余额字段（对 ERC20 而言是合约里记账） | 钱包账户本身通常**不存** SPL 余额，只存 SOL（lamports） |
| 「合约持币」 | address(this).balance / 合约地址的 token | 程序用 PDA 当 owner，持币在 PDA 名下的 ATA |

口诀：**Program = 逻辑；Account = 数据箱子；余额在箱子的 data 里。**

---

## 1. Account（账户）是什么

链上基本单位是 Account，每个有地址，核心字段：

| 字段 | 含义 |
|------|------|
| address | 公钥地址，或 PDA 地址 |
| lamports | SOL 最小单位；也用于交租金 |
| owner | 哪个 Program 有权修改该账户的 data**（见下文「两种 owner」） |
| data | 任意字节（Mint 信息、Token 余额、你们程序的配置等） |
| executable | 是否为可执行 Program |

三类常见账户：

1. **用户钱包（System Account）  
   - Account.owner = System Program  
   - lamports = SOL 余额  
   - data 基本为空  

2. Program（可执行账户）  
   - 存字节码 / 逻辑，类似「合约代码」  
   - 一般**不当**个人余额本  

3. 数据账户**（Mint、Token Account、金库配置等）  
   - `Account.owner` = 某个具体 Program（Token Program、你的 Program…）  
   - 业务状态在 `data` 里  

---

## 2. Program 是什么

**Program ≈ EVM 的智能合约代码。

- 用户发交易，带上一条或多条 Instruction**，指定：  
  - 调哪个 **Program ID  
  - 传入哪些 账户  
  - 指令 data**（参数）  
- Program 只能改 Account.owner == 自己 的账户的 data（或通过 CPI 让别的 Program 改它有权改的账户）。

常见 Program：

| Program | 作用 |
|---------|------|
| System Program | 创建账户、转 SOL |
| Token Program / Token-2022 | 增删改 Token Account 余额、Mint 等 |
| Associated Token Program | 按标准规则创建 ATA |
| 你自己写的 Program | 金库、抽成、「收进再转出」等业务 |

转 USDT 时：调用的是 **Token Program**，不是「去 Mint 账户里改 mapping」。

---

## 3. Mint 是什么

**Mint = 某一种代币的「身份证」账户**，描述币种元信息，**不存每个用户有多少币**。

Mint `data` 里常见字段：

- `supply`：总供应量  
- `decimals`：精度  
- `mint_authority`：谁能增发  
- `freeze_authority`：谁能冻结 Token Account  

例子：主网 USDT Mint ≈ `Es9vMFrzaCERmJfrF4H2FYD4KCoNkY11McCe8BenwNYB`。  
所有人的 USDT ATA，其 `data.mint` 都指向这个地址。

```
USDT Mint  ──只描述「这是什么币」──▶️  不存「张三有多少」
张三 ATA.mint = USDT Mint
李四 ATA.mint = 同一个 USDT Mint
```

---

## 4. Owner：两个完全不同的含义（必读）

### ① Account.owner（账户元数据）= **哪个 Program 能改这个箱子

每个账户都有，值几乎总是 Program ID**。

| 账户类型 | Account.owner |
|----------|----------------|
| 用户钱包 | System Program |
| Token Account / ATA / Mint | Token Program 或 Token-2022 |
| 你程序的配置账户 / 某些金库账户 | 你的 Program ID |

含义：只有该 Program 能改此账户 **data**。  
**不等于**「这些 USDT 属于 Token 程序」。

### ② Token Account data 里的 owner = **币属于谁

仅 SPL Token Account（等）的 data 布局里才有：

mint:   哪种币（Mint 地址）
owner:  谁有权花这些币（用户钱包 或 PDA）
amount: 余额（u64）

这才是口语里的「这个 token account 是谁的」。

### 对照

| 词 | 回答的问题 |
|----|------------|
| Mint | 这是**哪一种**代币？ |
| Account.owner | 哪个 Program 有权改这个账户的数据？ |
| data.owner | 这些代币**属于谁**（谁能授权转走）？ |

一张图：

用户钱包 W
  Account.owner = System Program          ← ①
  lamports = SOL

USDT Mint M
  Account.owner = Token Program           ← ①
  data: supply / decimals …               ← 币种定义

W 的 USDT ATA
  Account.owner = Token Program           ← ① 只有 Token Program 能改余额
  data.mint   = M                         ← 这是 USDT
  data.owner  = W                         ← ② 币属于用户 W
  data.amount = 100

金库：

Vault ATA
  Account.owner = Token Program
  data.mint   = USDT Mint
  data.owner  = Vault PDA                 ← ② 属于 PDA，程序可代签转出
  data.amount = …

## 5. 余额存在哪

### 原生 SOL

存在**钱包账户自己**的 lamports 字段（租金也占 lamports）。

### SPL Token（USDT / USDC 等）

存在独立的 Token Account**（通常是 ATA）的 `amount` 字段。

查余额流程：

1. 已知用户钱包 + mint  
2. 算出 ATA 地址  
3. 读该账户 `data.amount`  

（业务代码里常见：`FindAssociatedTokenAddress` / `TokenAccount(wallet)`。）

---

## 6. ATA（Associated Token Account）

**ATA = 按固定规则派生的、某钱包对某 Mint 的「标准」Token Account。

派生（概念上）：

ATA = PDA(
  seeds = [owner钱包, token_program_id, mint],
  program = Associated Token Program
)

性质：

- 同一 (钱包, mint, token program) → 唯一 ATA  
- Swap 里 toAddress 是用户 Sol 钱包**，不是 ATA；收款 ATA 由 `toAddress + toMint` **算出来  
- 若 ATA 尚不存在，交易里常带 `CreateAssociatedTokenAccountIdempotent`，创建后再收款  

随机地址当 token account？
| 做法 | 结果 |
|------|------|
| 随机地址当 `toAddress`（当钱包） | 会派生出「随机钱包」名下的 ATA → 无私钥则**丢币** |
| 硬塞随机 `destinationTokenAccount` | 账户不存在/mint 不对 → 交易失败**；碰巧是别人合法 ATA → **币进别人账户 |

结论：正常路径只用 标准 ATA**。

---

## 7. PDA（Program Derived Address）

**PDA = 由 Program + seeds 算出的特殊地址，没有私钥。

| | 普通钱包 | PDA |
|--|----------|-----|
| 私钥 | 有 | 无 |
| 谁能「当它」签名 | 持钥人 | 只有派生它的 Program**（`invoke_signed(seeds)`） |
| 用途 | 用户账户 | 程序金库身份、配置账户、权限账户 |

「钱进合约再转给你」时：

- Vault 的 Token Account：`data.owner = 某 PDA`  
- 程序用 seeds 证明自己是该 PDA，才能 CPI 调 Token Program 把币转走  

```
seeds = ["vault", mint, ...] + your_program_id
     → vault_pda
用户 USDT → vault_pda 的 ATA
程序 invoke_signed → vault ATA → 你的 ATA
```

**ATA vs PDA：

| | ATA | PDA |
|--|-----|-----|
| 是什么 | 一种标准 Token Account 地址 | 一种地址派生方式 |
| 谁派生 | Associated Token Program + 固定 seeds | 你的**（或指定）Program + 自定义 seeds |
| 典型用途 | 存某个 mint 的余额 | 当金库 owner、配置地址等 |

ATA 地址本身也是一种 PDA，但是 **ATA Program 按固定 seeds 派生的；业务金库 PDA 是 你的 Program 派生的。

## 8. 交易、指令、CPI（补全：钱怎么「动」）

### Transaction / Instruction

- Transaction（交易）**：一组指令的原子打包（要么全成要么全败）+ 若干签名  
- **Instruction（指令）**：调用某一个 Program，带账户列表 + 参数  

一笔 swap / 付款常见结构：

```
Tx
 ├─ (可选) 创建收款 ATA
 ├─ (可选) 创建 vault ATA
 └─ 你的 Program: pay / swap 相关指令
       └─ 内部 CPI → Token Program: transfer …
```

### CPI（Cross-Program Invocation）

程序在执行时**再调用**另一个程序，叫 CPI。  
例如：你的 Program → CPI → Token Program 做 `transfer`。

从 PDA 转出必须：

```
invoke_signed(
  Token Program 的 transfer 指令,
  账户列表,
  seeds  // 证明签名者是该 PDA
)
```

### 账户在指令里的角色（看文档/Explorer 常用）

| 标记 | 含义 |
|------|------|
| **signer | 该地址必须在交易上签名（或 PDA 通过 invoke_signed 等效签名） |
| writable | 本指令可能修改该账户（余额、data、lamports） |

Fee payer：付这笔 tx 网络费（SOL）的账户，通常是用户钱包。

---

## 9. 目标场景：用户把钱进「合约」，再转到你（同一 tx）

### 推荐模型

用户 ATA  --① transfer-->  程序 PDA 的 Vault ATA  --② CPI transfer-->  你的 ATA
                 \_____________ 同一个 Transaction _____________/

一条业务指令 `pay(amount)` 内顺序：

1. `token::transfer`：用户 ATA → Vault ATA（用户为 signer）  
2. `token::transfer` + `invoke_signed`：Vault ATA → 你的 ATA（PDA 签名）  

客户端组 一个 tx**（缺 ATA 则先 create idempotent）。

### 若中间不需要托管

可直接 `用户 ATA → 你的 ATA` 一条 transfer；  
Vault 适合：抽成、校验、条件支付、记账后再付。

### 注意

- 用户 / vault / 收款方都要有对应 mint 的 ATA  
- `pay` 内写死或严格校验收款人，防参数被改成任意地址  
- Token vs Token-2022：program id、ATA 派生都要一致  
- 同一 tx 内原子性：①② 同成同败  

---

## 10. 授权相关（补全：delegate）

除「owner 本人签名转账」外，Token Account 还可以：

- **Approve / Delegate**：owner 授权另一地址可花不超过额度的 token  
- 之后被授权方可在额度内 transfer，不必 owner 每次签转账逻辑  

设计收款程序时要分清：是 **用户当 signer 直接转进 vault**，还是 **先 approve 再由程序拉款**（体验不同）。

Mint 上还有：

- **mint_authority**：增发  
- **freeze_authority**：冻结某 Token Account（冻结后无法转）

## 11. SOL 与 WSOL（补全）

| | SOL | WSOL |
|--|-----|------|
| 存在哪 | 钱包 `lamports` | 像其它 SPL：WSOL Mint 的 ATA 里 `amount` |
| 和 DeFi | 很多池子要 WSOL | wrap：SOL→WSOL ATA；unwrap：关 ATA 取回 SOL |

Swap 到「原生 SOL」时，常先到 WSOL ATA 再 unwrap；协议参数里会有 `wrapAndUnwrapSol` 一类开关。

---

## 12. 租金 Rent（补全）

- 账户要保持一定 lamports，否则可能被回收  
- 实务上多用 **免租（rent-exempt）**：存够一笔 SOL，账户可长期保留  
- 创建 ATA 时，创建者通常要负担这笔免租准备金（可在关 ATA 时退回给接收方，视指令而定）

## 13. 在 Sol Explorer 上怎么看

推荐：Solscan / Solana Explorer。

### 打开对的地址

| 打开 | 能看到 |
|------|--------|
| **用户钱包 | Account.owner ≈ System Program；Token 列表；点进某个币才是 ATA |
| ATA 地址 | 同时看到 ① Program Owner 与 ② Mint / Owner / Balance |
| Mint 地址 | supply、decimals；**没有**「属于用户 W」的 data.owner |

### ATA 页上两个都叫 Owner 时

Overview
  Owner: Tokenkeg...              ← ① Account.owner（程序）

Token Account / Parsed
  Mint:   Es9v...                 ← data.mint
  Owner:  用户钱包或 PDA          ← ② data.owner
  Balance: …

口诀：

Account.owner  →  谁有权改这个箱子（程序）
data.owner     →  箱子里的币算谁的（钱包/PDA）
data.mint      →  箱子里是哪种币

## 14. 和 Swap 代码的对应（ms-swap 语境）

- `toAddress`：用户 Sol 钱包  
- 收款 ATA：`ToMint.TokenAccount(Recipient.Wallet)`  
  → `FindAssociatedTokenAddressAndBumpSeed(wallet, mint, tokenProgram)`  
- 缺 ATA：交易内创建（如 `create_recipient_to_token_account`）  
- Jupiter：`destinationTokenAccount` = 算好的收款 ATA（解包 SOL 时则用原生 destination）

## 15. 术语速查
| 术语 | 一句话 |
|------|--------|
| Account | 链上数据/程序的基本单位 |
| Program | 可执行逻辑（合约代码） |
| Instruction | 对某个 Program 的一次调用 |
| Transaction | 多条 Instruction 的原子打包 |
| CPI | 程序调用另一个程序 |
| Mint | 币种定义账户 |
| Token Account | 存某 mint 余额的账户 |
| ATA | 标准派生的 Token Account |
| PDA | 无私钥、由 Program+seeds 派生、可被程序代签的地址 |
| Account.owner | 哪个 Program 能改该账户 data |
| data.owner | Token Account 内：币属于谁 |
| lamports | SOL 最小单位；也用于租金 |
| Token-2022 | 新版 Token 程序；ATA 派生用其 program id |
| invoke_signed | 程序用 seeds 以 PDA 身份签名做 CPI |
